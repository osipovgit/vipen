# Проверки и границы изоляции

## Быстрые регрессии

Зависимости закреплены в `requirements-dev.txt`. Запускайте в отдельном контейнере/виртуальной среде разработки:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -p 'test_*.py' -v
ansible-playbook -i inventories/production/hosts.example.yml site.yml --syntax-check
ansible-lint --offline
yamllint .
bash tests/shellcheck-templates.sh
pre-commit run --all-files
```

Регрессии исполняют настоящие SQLite-операции и Bash-скрипты, отрендеренные Ansible. Границы Docker, systemd, UFW и Telegram заменены управляемыми заглушками. Сетевые подключения и отправка уведомлений не выполняются. Все тестовые значения синтетические, записи находятся в temporary directories.

Проверяются неоднозначные REALITY-селекторы, транзакционный отказ, ключи разных входов, WAL-snapshot, неверная схема, ошибка pull до остановки, ошибка миграции/старта с возвратом прежней пары БД/образ, принадлежность контейнера, закрытая сеть миграции, watchdog firewall, сохранение чужих правил, состав/ротация backup, зависший Docker, пустой/недоступный журнал, bootstrap и дедупликация дайджеста.

CI выполняет lint, эти регрессии и secret scan. GitHub Actions закреплены commit SHA; Python-пакеты — версиями. Dependabot предлагает обновления отдельно, без автоматического слияния.

## Практическая проверка 26 октября 2026

Лаборатория использовала Bubblewrap с отдельными user/PID/mount/network namespaces. `/usr`, библиотеки и исходники проекта монтировались только для чтения; рабочие файлы находились в отдельном `/tmp`-каталоге. В runtime-контейнере внешней сети не было. Сеть включалась только в отдельной среде загрузки инструментов. Системные службы хоста не изменялись.

Официальные Linux amd64 бинарники 3x-ui исполнялись в этой лаборатории:

- Первый запуск 3.11.0, настройка администратора и БД, loopback HTTP-панель и online backup работающего процесса.
- Реальная миграция синтетической БД 3.3.1 → 3.11.0 с двумя REALITY-входами на одинаковом порту; приватные ключи каждой записи сохранились.
- Возврат snapshot 3.3.1 и повторное открытие прежним бинарником.

SHA-256 архива 3.11.0 сверена с опубликованным release digest:
`0ddfa4702f595442e2962acd81addc768fdacaa4ff2672c971a0463dae744916`.

Это проверка приложения и миграции, **не** интеграционный прогон Docker Compose/systemd/UFW. Docker daemon на рабочей машине не устанавливался и не запускался. Конкретная production-БД не использовалась. Не проверены реальный клиентский REALITY-handshake, DNS, IPv6-маршрут, ARM64 и вся матрица ОС.

## Привилегированные системные тесты

Molecule проверяет базовые роли, journald, обновление пакетов и эффективную SSH-конфигурацию. Это узкий сценарий; он не покрывает весь site.yml. Запускайте его только в одноразовой VM/на ephemeral CI runner, не на рабочем компьютере и не на production. Privileged-контейнер не является достаточной границей безопасности от хоста.

Molecule job запускается только вручную через `workflow_dispatch` на GitHub-hosted runner. Docker socket, production secrets и файлы пользователя в тестовую VM передавать нельзя. После прогона уничтожайте VM. Частная cgroup namespace не делает privileged-контейнер равнозначным отдельной VM.

Перед production требуется отдельный полный сценарий на копии сервера:

1. Первое развёртывание и второй проход без лишних рестартов.
2. Новая независимая SSH-сессия до/после hardening; правильные IPv4/IPv6 CIDR; восстановление firewall после разрыва контроллера.
3. Реальные Docker pull/Compose, недоступный registry, плохая БД, неудачный старт и полный rollback.
4. Восстановление с другого носителя, включая сертификаты и точный образ.
5. Внешний VPN-handshake, DNS и передача данных; отказ VPS и внешний heartbeat.
6. Выключение каждого мониторинга и backup; таймеры не продолжают работу.

Поддержка версии ОС в preflight означает допустимую конфигурацию для тестирования. Отчёт о совместимости публикуют только после фактического прогона соответствующей ОС/архитектуры.
